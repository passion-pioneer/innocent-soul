### bco, bme, kms alb 앞에는 Sticky Session 활성화 하지 않음.




안녕하세요 신한 TA 오승현입니다.
가용성 테스트중인데요...아래와 같은 현상이 발생되는데 확인 부탁드리고자 글 올립니다.	 
1) 시나리오 - 4TPS 부하발생 중 KMS#1 프로세스 다운
2) 대상 - AWA Write 업무(/manage/biz/covert/sendTransaction)
3) 현상 :
case 1: 부하발생 중 KMS#1 중지 시,
-> 처리량 원복되지 않아 failover 실패, 간헐적으로 500 에러 발생
 case 2: 부하발생 중 kms#1  중지 후 재기동 
-> kms#1 중지 시 정상 failover 확인하였으나, 이후 재기동 시 1분간 간헐적으로 500 에러 발생

참고: read업무에서는 정상적으로  failover 확인하였으며, write업무에서만 발생하는 case


내부 이중화 환경(ALB로 로드밸런싱)에서 KMS에 대해 테스트를 해봤는데,
부하 상황에서 한 쪽 KMS를 내리게 되면, ALB가 내려간 서버에 대해 헬스 체크를 완료해서 로드밸런싱 대상에서 제외하기 전까지는 503에러가 지속적으로 발생합니다.
내려간 서버를 로드밸런싱 대상에서 제외하여 살아있는 서버로만 요청을 날리게 된 이후가 정상 failover 상황이 됩니다.
그리고 내려갔던 서버를 재기동 하게 되면, 마찬가지로 ALB가 대상 서버에 대해 헬스체크를 완료하여 로드밸런싱 대상에 포함하기 까지는 해당 서버에는 요청이 발생하지 않습니다.

전달해주신 내용만으로는 원인 파악이 어려운 상황이어서, 프로세스를 내렸을 당시의 awa의 로그나 kms 쪽 로그가 추가적으로 필요할 것 같습니다.


네 이중화 failover에 대한 예상flow는 말씀하신데로 재현되어야 하는게 맞는 말씀입니다. 다만  해당 부분이 그렇게 정상 동작하지 않아서...여쭤봤습니다. 로그는 추출해서 보내드리도록 하겠습니다. 감사합니다.


네 저희의 경우 KMS 앞에 있는 ALB에 직접 부하를 가하는 환경에서 테스트 했는데, 앞에 awa was가 포함된 경우에는 예상한 대로 동작하지 않을 수도 있어보입니다.
