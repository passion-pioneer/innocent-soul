NCP SFC의 동작 방식을 보면 목적지 CIDR은 SFC(Chain)에도 등록하는 것이 일반적입니다.

즉 목적지 CIDR(223.130.169.165/24)은 보통 다음 위치에서 사용됩니다.

위치	등록 여부	역할
서버 VPC Route Table	✅	Transit VPC로 보냄
Endpoint Route Table	✅	어떤 트래픽을 SFC에 태울지 결정
SFC Chain	✅	IPS → FW 순서로 통과시킴
IPS Route Table	✅	다음 Hop(FW)으로 전달
FW Route Table	✅	VGW 또는 목적지로 전달
다만 구분해야 하는 점
Route Table은 "어디로 보낼 것인가"를 결정합니다.
SFC Chain은 "어떤 보안 장비를 거칠 것인가"를 결정합니다.

즉 둘은 역할이 다르므로 둘 다 목적지 CIDR을 기준으로 설정되는 경우가 많습니다.

현재 구성을 보니 금융권에서 흔히 사용하는 Transit VPC + SFC + IPS + FW + VPN(VGW) 구조와 매우 유사합니다. 이런 구조라면 목적지 CIDR 하나를 추가할 때도 서버 RT → Endpoint RT → SFC → IPS RT → FW RT를 순서대로 모두 확인하는 것이 일반적인 운영 절차입니다.

그럼 routing table 등록하는 곳이 총 4군대인거죠?

네, 현재 설명해주신 구조라면 Route Table을 확인하거나 등록해야 하는 곳은 보통 4곳입니다.

순서	Route Table	역할
①	서버 VPC Route Table (b088-kr-prd-sbn-ap1-rt)	목적지 CIDR을 Transit VPC Connect로 전달
②	Endpoint(VTG) Route Table	해당 목적지를 SFC(IPS → FW)로 진입시킴
③	IPS Subnet Route Table	IPS를 통과한 후 다음 Hop(FW)으로 전달
④	FW Subnet Route Table	FW를 통과한 후 VGW 또는 목적지로 전달

여기에 SFC 자체의 Chain 설정도 있습니다.

즉, 구성 요소를 모두 나열하면 다음과 같습니다.

① Server Route Table      ← Route Table
② Endpoint Route Table    ← Route Table
③ IPS Route Table         ← Route Table
④ FW Route Table          ← Route Table
⑤ SFC Chain               ← Route Table 아님 (Service Chain 설정)
